# 固定经验回放

修改学习提示后，可用同一份已核验 train 经验比较候选生成行为，避免重复支付相同训练采集。运行前固定此诊断模式；它不是一次新的独立训练，也不是把旧轨迹算作新 Skill 的训练表现。

1. 保存源实验、Target State/模型/工具/任务版本、逐题最终答案、分数、完整轨迹及哈希。核实全体训练任务有效，实际访问边界通过；基础设施错误、缺题或来源未知的材料不进入回放。
2. 新建输出目录并冻结新方法版本。只向学习角色提供授权 train 轨迹、预测与约定反馈；空 Wiki 开始，不导入旧提案、语义审计、validation/test 逐题记录或标准答案。保存来源清单，原记录只读。
3. Maintainer 重建 Wiki，Proposer 实际读取至少四个不同训练任务的完整轨迹并提出一个改动，Auditor 按当前协议核对。训练内推演不调用 Target 或试分。若适配器重新核验缓存答案，单独记录为评分复核，不算新训练。
4. 已有 H0 validation 仅在实际 Target State、模型/工具/任务版本、时限、评分和题目集合相同且原证据完整时复用；记录复用 ID。学习方法改版本身不改变空技能 H0，但须逐项确认其确实未改变 Target 条件。否则重新测 H0。
5. 合法候选进行新一次完整 validation；仍只接受严格超过冻结历史最佳。接受后按已冻结测试计划评测，拒绝时不把空技能再测的波动算成技能收益。不得因结果不满意继续回放直至通过。

回放次数、修订次数及 test 重复次数应事先固定。报告明确哪些分数/轨迹沿用、哪些重新生成，费用包含历史与本次调用。若继续正常下一轮优化，必须使用当前 accepted Skill 重新跑 train；不能沿用空技能经验声称完成了该轮。
