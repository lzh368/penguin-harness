# 从训练经验编译可复用的解题方法

**学习目标：在什么条件下，读取哪些数据，依据什么规则，执行哪些查询、关联、计算或操作，得到什么中间结果，最后如何用于完成任务。** Maintainer 在 Wiki 保存这条操作链，Proposer 将有依据的方法编译成 Target 能执行的 Skill，Auditor 核对方法是否成立，固定 validation 决定是否接受。

“认真分析、全面检查、多查资料、检查一致性”不能单独构成方法，必须说明具体怎么做。查询、计算、业务判断、格式处理都可以成为技能，只需明确解决的问题；不强制每个 Skill 都写业务分类规则，也不因检查容易描述就忽略更有依据的解题流程。

**一个 Skill 可以包含围绕同一业务目标的完整多步流程。** 单次 create/patch 一个技能，不是只能增加一个小检查；也不要求覆盖全部训练题。禁止把互不相关的功能拼成总清单。既可编译 Target 已做过的有用步骤，也可修正有证据的行为缺口；不要求发明新动作或提前证明提分。

角色只使用冻结协议授权的 train 材料和历史资料。`score_only` 下没有训练标准答案，不能从总分反推私有标签；validation/test 的题目、逐题分数、答案、轨迹和 rubric 均不供学习角色读取。本指南不增加学习信息、不改采样、单候选、接受阈值或评分规则。

## 1. Maintainer：保存操作链，而不只是失败现象

按 [training-views.md](training-views.md) 读取本轮采样清单和授权视图，先确认覆盖与截断。每个选中的经验用短表或短段记录：

> 任务目标 → 所需输入及来源 → 实际执行步骤 → 最终产物 → 已知反馈 → 可复用方法及边界。

附 train 入口和消息、行号或事件位置；命令、查询或计算片段只保留解释方法所需的部分，参数留给当前任务，不复制题目答案。围绕同一目标合并重复经验，保留反例及适用条件。标题、索引和正文表达同样的确定性；新证据推翻旧解释时同步修正，不能让索引继续推荐已被撤销的规则。

分别标出四种来源：

| 来源 | 能支持什么 |
|---|---|
| 题面明文规则 | 相应任务的要求、约束与定义，不自动成为所有任务的规则 |
| 工具返回事实 | 实际取得的记录和操作结果；查询的范围、完整性和时效仍需核对 |
| Target 自己的推断或自检 | 观察到它采用了某种解释、某段检查通过；不因此证明解释正确 |
| 授权评分反馈 | 实际得分或明确反馈；总分不能定位哪一步正确、错误或导致变化 |

没有满分样本也可以学习。保留有依据的正确子步骤和局部失败；同一种做法出现在高分、低分任务中时都要记录，不把其中一类写成不存在该行为。一个观察的重复转述不是多份独立支持。

沿操作链区分取数缺口、规则解释、计算/操作、最终交付。中途失败后来已修正，就记录修正过程；不能把被放弃的方案当成最终错误。自检 OK 不能排除它未覆盖的业务错误。系统提示词、上轮技能和引擎控制记录不是本轮新经验；上下文压缩时未执行的工具请求不算真实工具失败。

视图未显示的环节写明缺口，不等于 Target 没做；Proposer 再查完整轨迹。Maintainer 只修改 `wiki/index.md`、`wiki/patterns/*.md`、追加 `wiki/logs.md`，不改 raw、技能、skill-impact 或分数。无新模式时记日志即可。

## 2. Proposer：选择方法，写出实际能执行的正文

从 Wiki、历史 `skill-impact.md`、训练摘要和当前 accepted Skill 开始，**至少完整阅读本轮、同一 accepted 快照下四个不同训练任务的轨迹**，包括入口列出的全部分片和子轨迹。四份摘要或路径存在不能替代实际阅读；材料或预算不足时报告未完成，不声称已覆盖。

先用原记录复核 Wiki，再比较候选方向的依据、适用范围、预期作用和额外成本。记录已经齐全但业务解释出错时，不能仅用更多检索声称解决；原本已做的有用操作仍可编译，但如实说明是复用，不说成修复了不存在的遗漏。不按模式出现次数、篇幅或“看起来全面”选方向，不增加额外候选试分。

### Skill 正文的组织方式

建议按以下顺序表达，不新增 JSON 字段，也不要求固定标题：

1. **适用条件**：当前任务出现什么可观察的要求或输入时使用。
2. **所需信息**：需要哪些数据、规则、字段，从哪些允许的来源取得。
3. **执行方法**：具体查询、关联、计算或判断步骤，必要时包含相连的多个步骤。
4. **结果用途**：产出什么中间结果，如何用于完成当前任务。
5. **分支与边界**：什么条件下改用另一分支、跳过或停止该方法，如何处理冲突。

Target 收到完整 `SKILL.md`，看不到 PURPOSE/Wiki；名称或 description 不能阻止正文在不相关任务生效。适用范围要覆盖每个必需步骤，特殊字段放进条件明确的分支。参数、阈值、实体 ID、时间范围及来源优先级由当前任务提供或核实，不固化训练常量、题目 ID、固定任务路径或某次答案。

每个步骤说明输入如何变成结果。已有正确结果无需为执行技能而重做；只修改当前任务允许的范围。内部证据表、自检记录不自动成为最终交付物，不向答案添加任务未要求的字段、报告或文件。单项检查完成不等于整题完成。

### PURPOSE 说明为什么这个方法值得提出

简要给出：方法目标；编译已有做法还是修正缺口；训练证据位置；输入与规则依据；适用边界、反例或未覆盖情形；与旧技能的关系及实质变化。证据 ID、历史分数和演变说明留在 PURPOSE，不混入 Target 的方法正文。

至少展开一个真实已读训练场景：**可见条件 → 原动作与最终产物 → Skill 的具体步骤 → 可核对的中间结果 → 如何用于交付**。再检查另一已读场景的边界或原有正确操作；没有合适对照就记未覆盖，不编造反例。仅列四个引用或写“可能更准确”不构成推演。

这是使用现有记录的推演，不重跑 Target、不调 judge、不增加候选数量。可以不知道收益，但必须有操作依据。规则没有在任何支持场景触发时补证据或 no_action；只改“不确定”的措辞而没有查询、处理或交付变化，不能声称修复了计算。

对已有技能优先局部修补。只有当前 accepted 已完整覆盖且没有实质修改时才是重复提案；不能因为 Target 曾主动做过某个步骤就禁止编译。后续轮次检查旧规则在本轮 train 中未触发、未遵循，还是执行后仍有缺口；拒绝后需要新训练依据或实质修正，不能仅换名称、措辞。一次仍只 create/patch 一个技能；确无有据改动可返回 no_action。

## 3. 方法成立的依据：不同检查解决不同问题

不要求业务推理都能逐字引用题面。可以结合明确要求、允许的记录、工具反馈和适用领域知识提出解释并核查；必要前提要能对应到证据，不能由字段名或自拟断言冒充。

| 操作 | 应核对的依据与边界 |
|---|---|
| 查询与完整性 | 依据接口契约、记录 ID、过滤谓词、游标或总数判断；相同/整齐的条数只是线索，不证明过滤失效或分页。找到单条记录不代表关联核查或总体汇总完成；有限空查询不证明不存在。 |
| 业务判断 | 枚举列出允许的值，不决定当前记录该用哪个值；未知不自动等于 false、not-met 或空列表。若任务明确规定默认规则，才使用该规则。 |
| 总体与汇总 | 先按时间、实体、去重和状态定义确定纳入记录，再算分类、比例和排名；算术自洽不能证明纳入集合正确。legacy、mirror、note 等名称本身不决定信息是否可舍弃。 |
| 字段关系与一致性 | 各字段有定义，不代表互斥、包含或先后关系成立；核对实体、时间及状态维度。当前事实、历史事件和下一步处置不能自动合成一个状态。 |
| 格式与交付 | 核对结构、类型和明确的顺序等约束；结构合法不证明内容正确。只结束该项检查，任务剩余要求仍须完成。 |

模板既可能给结构也可能给业务定义，要分别读含义；输出没有某字段，不证明该输入无关，同名也不证明可以直接复制。任务材料称“不要照抄”不等于“忽略”。来源冲突时提供核对路径，不用固定的“模板优先”或“选择最自然解释”替代依据。

可以缓存已核对的定义和计算，减少重复推理，同时保留依赖。临时假设不能因“只决定一次”变成强制规则；原有材料出现矛盾也允许修正，不必等到新增事实。修改上游解释后只重算受影响结果。核查无新增信息时停止该检查，按当前任务要求继续推理；不无限搜索、不探测评分或标签接口，也不用猜数据生成器/评分习惯来选业务规则。

自写断言与按同一假设生成的答案相符，只证明内部自洽。检查失败时核对任务约束、检查实现和产物，可能改答案，也可能有依据地改检查；不能规定“永远只改答案”，也不能为消除失败删掉明确约束。操作依据成立、效果未知的候选可交 validation；缺少必要业务前提不能只记成收益 warning。

### 合成例子：编译一个完整操作流程

任务明确要求按账户汇总未结清金额。训练记录 A 的两行原金额为 100、60，已结清金额为 40、10；Target 直接累计原金额 160。可提出一个相连流程：按任务定义关联同一账户的结清记录 → 确认金额单位和截止时间 → 逐行算未结清额 60、50 → 按账户汇总 110 → 核对 160 = 50 + 110 → 用汇总值填写任务指定字段。它是一个 Skill 的多步方法，不是六个独立补丁；中间计算可由输入验证，不依赖评分答案，也不证明整题一定提分。

记录 B 已正确算出未结清额时直接复用，不强制重算。若任务要求原金额，跳过该方法；缺少结清记录时查允许来源，不能自行假定全为零。例子只说明方法结构，不得复制为正式训练证据或 benchmark 业务规则。

## 4. Auditor：按实际正文验证方法，不按材料数量放行

先核对真实 diff、角色访问、State 和技能装载，以及 Proposer 阅读四个不同完整训练任务的记录。沿一个引用场景，**只按 Target 实际收到的 SKILL** 走一遍：输入存在或可合法取得吗；规则前提成立吗；步骤能得到所声称的中间结果吗；会改变哪些原有正确操作；边界是否写在正文。再查 PURPOSE 的另一个边界场景。不能用 PURPOSE 未注入的限定词替正文补前提。

正文要求“关系明确成立”，推演却只有两个字段名时，不能声称分支已经触发；要补关系依据或改成有据的查证步骤，不能无依据地放宽入口。候选可编译已观察到的做法，无需先证明收益，也不要求穷举未来场景。

| 核查结果 | 处理 |
|---|---|
| 操作前提有据，训练推演与正文相符，只剩效果未知 | `pass`；可记收益 warning，交固定 validation |
| 关键证据缺失、读取不完整、触发条件/中间结果无法核实 | `unverified`；明确补什么，不进入 stage |
| 与已读记录矛盾、把已修正的中间错误写成最终错误、强加无依据默认规则，或忽略已知边界 | `fail`；指出具体冲突，先修正 |
| 缺前提却声称已触发、仅凭自检证明业务正确、查找结束等同整题完成 | 证据不足为 `unverified`；明确冲突为 `fail`，不能降为措辞 warning |
| 输入、步骤和用途明确，只是与某次 Target 原有做法相同，或没有成功对照 | 不能单凭这些拒绝；查其复用价值、范围及与 accepted 是否重复 |

引用数量、文件齐全、写了“待验证”都不能替代上述核对；拼写等不改变执行含义的问题可记 warning。Auditor 不创造技能、不预测验证分、不读取 held-out 内容、不调模型做题。

关键缺口在 stage 前由原学习角色依据 train 材料修订并重新审计，保留各版及回执；工具不支持安全修订时停止，不覆盖既有提案或 pending。修订不增加试分。访问审计分别记录尝试、实际返回和披露：404/拒绝不等于从未探测；按冻结协议处理越界，不用网络白名单或评分正常替代实际调用核查。
